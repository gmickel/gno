# Name-match boost for keyword search (#372)

## Overview

Add an opt-in name-match boost inside `SqliteAdapter.searchFts` so documents whose title or filename matches the lexical query rank first in BM25 keyword search and hybrid BM25 retrieval without altering `FTS5_FIELD_WEIGHTS`, unboosted callers, or body-only ranking.

Source issue: https://github.com/gmickel/gno/issues/372 (reported by @DanielKillenberger).

## Acceptance Criteria

- **R1 (Opt-in flag and caller scoping)**: Add `nameBoost?: boolean` on `FtsSearchOptions`. Enable it in `src/pipeline/search.ts` (`searchBm25`, overridable internally so `src/core/memory-recall.ts` stays unboosted) and `searchFtsChunks` in `src/pipeline/hybrid.ts`. Leave `src/core/memory-recall.ts`, `src/core/memory-remember.ts`, and `src/core/activation-probe-plan.ts` unboosted. No config key, no CLI flag, no env var.
- **R2 (Single-scan SQL candidate pool)**: When `nameBoost` is enabled, compute raw BM25 (`score`) and title/filepath-only BM25 (`name_score`, body weight `0.0`) in one `MATERIALIZED` CTE (`all_matches`), union top `limit` by `score` with top `50` where `name_score < 0` ordered by `name_score`, and raise outer `LIMIT` to `limit + 50`. Keep `FTS5_FIELD_WEIGHTS` unchanged. When `nameBoost` is off, SQL and results remain byte-for-byte identical to today.
- **R3 (Coverage and multiplier scoring)**: Have `buildFts5Query` return distinct positive query terms (expanding quoted phrases and hyphenated compounds; excluding negated terms). Tokenize document title and filename stem (last segment of `rel_path` without extension; directories excluded) with `/[\p{L}\p{N}]+/gu` lowercased. Match a query term to a name token when `term.length >= 3 && token.startsWith(term)` or `token === term`. Compute `q = matchedTerms / terms.length` and `n = Math.min(matchedName, matchedTerms) / nameTokens.length`. Take the larger multiplier of title vs filename: `3` when `q === 1 && n === 1`; `1 + (q * n) ** 2` when `q === 1 || n === 1`; `1` otherwise. Keep named constants (`candidateLimit: 50`, full-match bonus, `minPrefixLength: 3`) in one block next to `FTS5_FIELD_WEIGHTS`.
- **R4 (Post-boost ordering and `minRelativeScore`)**: Multiply raw negative BM25 score by the multiplier, sort ascending by adjusted score, and slice to `limit`. Compute `minRelativeScore` floor from the best unboosted score so a boosted top row does not drop ordinary rows below the floor.
- **R5 (Measurement parity on real index snapshot)**: Reproduce prototype results on Gordon's index snapshot (~97.8% name-lookup hit@1 average vs ~64.3% baseline; body-text suites unchanged at 20.0 / 36.3 / 58.3; keyword search p95 latency within 15% of unboosted).
- **R6 (Unit, integration, and tokenizer tests)**: Add `bun test` coverage for coverage/multiplier unit cases (including 1-letter non-prefix match, 1-word title vs 6-word query cap `1 + (1/6)^2`, repeated title word cap), generated corpus store/pipeline scenarios (issue #372 with/without H1, filename-only, title + extra word, body-only parity, flag-off parity, `minRelativeScore`, `anyTerm`, quoted phrase, negation, collection/eligibility filters, memory recall unchanged), and tokenizer safety (`unicode61`, `porter`, `trigram`, `snowball`, CJK). Leave nothing in TMPDIR.
- **R7 (Documentation and changelog)**: Update `docs/adr/002-bm25-query-semantics-and-weighting.md`, `docs/CLI.md`, `spec/cli.md`, `CHANGELOG.md` (under `[Unreleased]`, crediting @DanielKillenberger for #372), and prepare matching `~/work/gno.sh` docs PR without touching legacy `website/`.
- **R8 (Gates, evals, live QA, review, PR)**: Pass `bun run lint:check && bun run test:tmp-check`, verify eval scores unchanged (`vsearch`, `query`, `hybrid`, `eval:memory`, `eval:sessions`), capture isolated live CLI QA before/after, run `gpt-6.2-sol` medium review via Codex backend, and open PR with `Ref #372` (no merge, no release, no issue comment).
