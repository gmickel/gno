## Actual native bytes: available API and provenance

### Preferred context-specific counter

The native AddonContext has:

`context._ctx.getMemoryBreakdown(): {cpuRam:number,gpuVram:number}`

This is an internal API, accessible from the actual LlamaContext returned by model.createContext. It is appropriate for a pinned development-only acceptance hook, not a new product API.

Evidence chain:

- `node_modules/node-llama-cpp/dist/bindings/AddonTypes.d.ts:164`: native-context method declaration.
- `llama/addon/AddonContext.cpp:764`: rejects disposed/unloaded contexts, then calls the real loaded context's `ctx->memory_breakdown()`.
- Line778 sums each backend's `memoryBreakdown.context + memoryBreakdown.compute`, classifying host buffers as CPU and GPU/IGPU device buffers as GPU.
- It returns those byte totals as cpuRam/gpuVram. It does not call the GGUF resource estimator or the state serialization-size API.

Correct metric name: **native-reported context plus compute buffer bytes, by backend**. It excludes model-weight allocations and does not purport to capture every driver/runtime/JavaScript/OS allocation. On unified-memory Metal, report CPU/GPU classifications and the native-accounted total without interpreting them as two physically independent memory pools. Preserve raw values and avoid double-counting them again with RSS/device-used totals.

### Public aggregate cross-check

`await model.llama.getLlamaMemoryUsage()` returns `{gpuVram,cpuRam}`.

Despite its implementation using “marked” counters, these are **actual native allocation accounting**, not the pending resource estimates:

1. `dist/evaluator/LlamaContext/LlamaContext.js:687` reserves estimated bytes temporarily for admission.
2. After the real native context init succeeds, line711 calls `context._ctx.getMemoryBreakdown()`.
3. Lines712–713 mark that actual result in the VRAM/RAM orchestrators.
4. Estimated reservations are released.
5. Context disposal releases the corresponding marks (`LlamaContext.js:135`).
6. Model loading similarly marks the loaded model's actual native memory breakdown (`dist/evaluator/LlamaModel/LlamaModel.js:596`).
7. Public `getLlamaMemoryUsage` (`dist/bindings/Llama.js:282`) reads the orchestrators' markedMemory, while `MemoryOrchestrator.js` keeps estimated reservedMemory separate.

For a child containing exactly one model and no other contexts, the aggregate increment from loaded-model-only to context-created should cross-check the context-specific breakdown. Record the model's own allocation separately if needed.

Limitation: aggregate context marks are populated at creation and removed at disposal; the inspected code does not refresh them on each score. Query the **direct native context breakdown again after cold and warm scoring** to detect any subsequent native accounting change. Do not assume a static aggregate tracks a dynamically enlarged compute buffer.

### Admission before any auto allocation

A credible new condition requires more than a normal-pressure screenshot:

- Stable physical/free/unified-memory observations with compressor/swap trend and no prior owned allocations, measured near the intended run.
- Conservative model+native-auto-context+compute/batch+child-runtime requirements, including a reserve. Use GGUF estimates only for this admission decision, explicitly labelled estimates.
- Evidence that the unchanged full-offload/model settings fit the governor and physical headroom. CPU/offload changes, smaller batch, new precision or ignoreMemorySafetyChecks are prohibited ways to make it fit.
- One GPU owner, bounded process ancestry/cleanup and the host-approved existing safety policy unchanged. No termination of unrelated processes, no memory purge/service restart, and no auto allocation merely to discover whether it will pressure-stop again.

**Current snapshots do not establish these conditions.** The conservative option is to leave the auto arm unstarted and report R3 Metal incomplete. A different physical Metal host with verified sufficient memory could be an independently declared alternative if the host authorizes it; do not imply such a host is available or silently substitute platforms.
